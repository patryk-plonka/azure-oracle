# Observability Floor — Request/Error Logging Middleware with Secret-Stripping — Implementation Plan

## Overview

Build F-04: a request + error logging middleware that emits one line per request
(method, path, status, duration) and a scrubbed traceback on unhandled
exceptions, with all secrets stripped from both logs and the 500 error response
body. Uses stdlib `logging` only — no `structlog`, no correlation IDs (FR-014 is
Parked). This is the minimal logging floor the PRD NFR requires, sequenced before
S-01 so the "no secrets in logs" guardrail is enforced before the first
end-to-end query exercise.

## Current State Analysis

Phase 1 introduced stdlib request/error loggers, a custom 500 response, and
uvicorn access-log suppression. During Phase 2, the installed Starlette
middleware stack disproved the plan's `BaseHTTPMiddleware` assumption:
handled `HTTPException` responses (401/403) are generated by the inner
`ExceptionMiddleware`, while the generic `Exception` handler runs in the
outer `ServerErrorMiddleware`. A `BaseHTTPMiddleware` implementation therefore
cannot provide a single reliable observation point for all required statuses.

The correction is a pure-ASGI request logger that observes response-start
messages for normal and handled-error responses, plus handler-owned 500 request
and error logs. Tests must also isolate application loggers explicitly because
the production loggers do not propagate to pytest's root capture handler.

`database.py:11-26` already redacts `DATABASE_URL` from its configuration errors
— prior secret-stripping art F-04 extends to all logs and HTTP error bodies.

## Desired End State

A deployed FastAPI app where:
- Every request emits one log line: method, path, status code, duration (ms) — via a dedicated logger (`"azure_oracle.request"`)
- Every unhandled exception (500 path) emits a scrubbed traceback (frame locals stripped) via `"azure_oracle.error"`, and the 500 response body is `{"detail": "Internal Server Error"}` with no secret leakage
- The `Authorization` header is never logged in full — redacted to `Bearer ***` in any log that references it
- No secret or token value (raw token, `access_token`, `SECRET_KEY`, `TOKEN_HASH_SALT`, `DATABASE_URL`, `GITHUB_OAUTH_CLIENT_SECRET`) appears in any log line or error response body, including on the error/exception path
- Uvicorn's default access log is silenced (`--no-access-log` in `railway.json`); the middleware is the sole request logger
- Uvicorn's error-logger traceback is suppressed via a `logging.Filter` on `"uvicorn.error"` that drops records with `exc_info` (the "Exception in ASGI application" records), so the middleware's scrubbed traceback is the sole error log — uvicorn's traceback (which does not capture frame locals, but is redundant) is filtered out
- The logging middleware runs outermost (added after `TrustedHostMiddleware`), so it logs even host-rejected 400s
- `GET /health` remains public and unchanged; all existing routes continue to work
- Tests verify the secret-stripping guardrail on both the success path and the error/exception path (Risk #4)

## What We're NOT Doing

- **No structured/correlated logging** — FR-014 is Parked; no JSON logs, no correlation IDs, no `structlog`
- **No request body logging** — only method, path, status, duration; bodies are never logged (the `/auth/token` response body contains the raw token)
- **No response body logging** — same reason; the middleware logs the status code, not the body
- **No metrics** — no Prometheus, no counters; the PRD NFR is a logging floor, not a metrics floor
- **No audit trail** — FR-015 is Parked; the logging floor evidences EULA/license events via request logs, not a dedicated audit table
- **No new packages** — stdlib `logging` only, consistent with F-03's zero-new-packages posture
- **No app-factory refactor** — middleware registers on the existing `app` in `main.py`; tests use the real `app` via `TestClient` as today
- **No changes to existing `HTTPException` detail strings** — they already contain no secrets; F-04 adds the 500 handler, not changes to 4xx handlers

## Implementation Approach

**One root-level module** (`logging_middleware.py`) containing:
1. A `_scrub_headers(headers)` utility that redacts `Authorization` to `Bearer ***` and leaves other headers untouched.
2. A `_scrub_traceback(exc)` utility that formats a traceback with frame locals replaced by `<redacted>` — preserving the exception type, message, and call stack file/line/function names (the debugging signal) while stripping all local variable values (the leak risk).
3. A pure-ASGI `RequestLoggingMiddleware` that records request timing and logs each observed `http.response.start` (method, path, status, duration) at INFO via `"azure_oracle.request"`.
4. Small logging helpers shared by the ASGI middleware and 500 handler, so the handler can emit the 500 request line and scrubbed traceback that user middleware cannot observe.

**One exception handler** registered in `main.py` via `@app.exception_handler(Exception)` that logs the 500 request and scrubbed exception before returning `{"detail": "Internal Server Error"}`. `ServerErrorMiddleware` re-raises after the handler runs, so a `logging.Filter` on `"uvicorn.error"` drops only records carrying `exc_info`; the middleware/handler logs remain the sole application request/error records.

**Middleware ordering**: `app.add_middleware(RequestLoggingMiddleware)` added *after* the `TrustedHostMiddleware` line (`main.py:57`), so it wraps outermost and logs all requests including host-rejected 400s.

**Uvicorn access log silenced**: `--no-access-log` added to the uvicorn start command in `railway.json:4`, so the middleware is the sole request logger (no duplication).

**Tests**: `tests/test_logging_middleware.py` using closed `TestClient` contexts, a direct per-test in-memory handler on the non-propagating named loggers, and the existing `seeded_token` fixture. The suite covers 200, 401, 403, and a temporary 500 route without permanently mutating the singleton app.

## Critical Implementation Details

- **Middleware ordering is load-bearing**: `app.add_middleware` wraps the app — the *last* added runs *outermost*. `RequestLoggingMiddleware` must be added *after* `TrustedHostMiddleware` (line 57) to run outermost and log host-rejected 400s. Adding it before line 57 would place it inside TrustedHost and hide rejected requests.
- **Exception handler controls the 500 response body; a logging filter suppresses uvicorn's redundant traceback**: the custom `@app.exception_handler(Exception)` returns a `JSONResponse` so the 500 body is `{"detail": "Internal Server Error"}`. However, `ServerErrorMiddleware` **always re-raises** after the handler runs (`errors.py:185`), so the exception propagates to uvicorn's `run_asgi` (`h11_impl.py:421`), which logs a second traceback via `"uvicorn.error"` with `exc_info=exc`. Uvicorn's formatter does **not** use `capture_locals=True` (no frame locals leak), but this produces a redundant unscrubbed traceback. A `logging.Filter` on the `"uvicorn.error"` logger drops records where `record.exc_info is not None` (or where the message starts with "Exception in ASGI application"), so the middleware's scrubbed traceback is the sole error log. The filter must not suppress non-traceback error logs (startup errors, etc.).
- **Starlette's error layers determine logging ownership**: the stack is `ServerErrorMiddleware` -> user middleware -> `ExceptionMiddleware` -> routes. The pure-ASGI middleware sees `http.response.start` for 200/401/403 responses emitted by the inner layer. A generic exception escapes user middleware and is converted to the 500 response by outer `ServerErrorMiddleware`, so the registered `Exception` handler must emit both the 500 request log and scrubbed error log. Do not duplicate either log in the user middleware.
- **The test app is a singleton**: each test must use `with TestClient(app, base_url="http://localhost")` and a fixture that attaches a new in-memory handler directly to `azure_oracle.request`, `azure_oracle.error`, and `uvicorn.error`, then restores logger levels and removes the handler in teardown. A temporary raising route must be removed from `app.router.routes` after each 500 test.

## Phase 1: Logging Middleware + Error Handler + Wiring

### Overview

Create the logging middleware module, register it in `main.py` (outermost), add the 500 exception handler, and silence uvicorn's access log in `railway.json`.

### Changes Required:

#### 1. Create `logging_middleware.py`

**File**: `logging_middleware.py` (new file at project root)

**Intent**: A root-level module containing the secret-scrubbing utilities and the `RequestLoggingMiddleware` class, following the F-03 convention of root-level modules (not packages).

**Contract**:

- `_scrub_headers(headers: dict[str, str]) -> dict[str, str]`: returns a copy with `Authorization` → `"Bearer ***"` (case-insensitive header name match); all other headers unchanged.
- `_scrub_traceback(exc: Exception) -> str`: returns `traceback.format_exc()` output with all frame local variable values replaced by `"<redacted>"` — preserving file paths, line numbers, function names, and the exception type/message. The implementer should use `traceback.extract_tb` to rebuild the string without locals, or regex-replace the `locals` section of the formatted traceback. The middleware must format the traceback via `_scrub_traceback(exc)` and pass it as a string argument to `logger.error` — do NOT pass `exc_info=exc`, which would trigger the formatter's default traceback (redundant with the scrubbed string).
- `SuppressUvicornTracebackFilter(logging.Filter)`: a filter that drops records where `record.exc_info is not None` on the `"uvicorn.error"` logger — these are the "Exception in ASGI application" records uvicorn emits because `ServerErrorMiddleware` re-raises (`errors.py:185`). The filter must NOT drop records without `exc_info` (startup errors, config errors, etc. pass through).
- `RequestLoggingMiddleware(BaseHTTPMiddleware)`:
  - `__init__` takes no config beyond `app`; uses module-level `logger = logging.getLogger("azure_oracle.request")` and `error_logger = logging.getLogger("azure_oracle.error")`.
  - `async def dispatch(self, request: Request, call_next) -> Response`:
    - Record `start = time.perf_counter()`.
    - Call `response = await call_next(request)`.
    - Compute `duration_ms = (time.perf_counter() - start) * 1000`.
    - Log `logger.info("%s %s %d %dms", request.method, request.url.path, response.status_code, duration_ms)`.
    - On `Exception` as `exc`: log `error_logger.error("Unhandled exception: %s\n%s", type(exc).__name__, _scrub_traceback(exc))`, then re-raise (so the exception handler returns the 500 response).
    - Return `response`.
  - **No request body or response body is logged.** No headers are logged in the request line (the `Authorization` header is never referenced in the INFO log).

#### 2. Register middleware + exception handler in `main.py`

**File**: `main.py`

**Intent**: Wire the logging middleware as the outermost layer and add a custom `Exception` handler that returns a clean 500 response, suppressing Starlette's default traceback logging (which includes frame locals).

**Contract**:

- Import: `from logging_middleware import RequestLoggingMiddleware, SuppressUvicornTracebackFilter` (near the existing `from starlette.middleware.trustedhost import TrustedHostMiddleware` at line 13).
- After the existing `app.add_middleware(TrustedHostMiddleware, ...)` line (`main.py:57`), add: `app.add_middleware(RequestLoggingMiddleware)`. This registers it outermost (last added = outermost wrapper).
- Install the `SuppressUvicornTracebackFilter` on the `"uvicorn.error"` logger so uvicorn's redundant traceback (emitted because `ServerErrorMiddleware` re-raises) is dropped:
  ```python
  import logging
  uvicorn_error_logger = logging.getLogger("uvicorn.error")
  uvicorn_error_logger.addFilter(SuppressUvicornTracebackFilter())
  ```
  This must run at module level (after `app` creation) so the filter is in place before any request is served. The filter drops only records with `exc_info` (traceback records); non-traceback error logs pass through.
- Add a custom exception handler for unhandled exceptions:
  ```python
  from fastapi import Request
  from fastapi.responses import JSONResponse

  @app.exception_handler(Exception)
  async def unhandled_exception_handler(request: Request, exc: Exception) -> JSONResponse:
      return JSONResponse(status_code=500, content={"detail": "Internal Server Error"})
  ```
  This returns a clean 500 body and prevents Starlette's `ServerErrorMiddleware` from logging the full traceback with frame locals. The middleware's `dispatch` `except` block logs the scrubbed traceback before this handler runs.
- **No new env vars required** — the middleware uses stdlib `logging` defaults; no `LOG_LEVEL` env var (keep it simple; uvicorn's `--log-level` controls root level). If a `LOG_LEVEL` is desired later, it follows the `main.py:23-39` fail-fast pattern, but F-04 does not add it.

#### 3. Silence uvicorn access log in `railway.json`

**File**: `railway.json`

**Intent**: Add `--no-access-log` to the uvicorn start command so the middleware is the sole request logger (no duplication).

**Contract**: Update `deploy.startCommand` to:
```
uv run alembic upgrade head && uv run uvicorn main:app --host 0.0.0.0 --port $PORT --no-access-log
```

## Testing Strategy

### Unit Tests:

- `_scrub_headers` and `_scrub_traceback` utilities can be unit-tested directly (no `TestClient` needed): pass a dict with `Authorization` → assert redacted; pass an exception → assert formatted traceback has no local variable values.

### Integration Tests:

- `tests/test_logging_middleware.py` (Phase 2) covers the full pure-ASGI
  middleware + exception-handler chain using isolated direct logger handlers
  and closed `TestClient` contexts. It exercises 200, 401, 403, and 500 paths
  without persisting test-only routes or logger configuration. This is the Risk
  #4 verification surface.

### Manual Testing Steps:

1. Start the app with `uv run uvicorn main:app --host 0.0.0.0 --port 8000 --no-access-log` and confirm only `"azure_oracle.request"` logs appear (no `"uvicorn.access"` lines).
2. `curl http://localhost:8000/health` → confirm one INFO log line with method, path, status, duration.
3. `curl -H "Authorization: Bearer <real-token>" http://localhost:8000/auth/probe` → confirm 200 and the log line does not contain the raw token.
4. `curl http://localhost:8000/auth/probe` (no token) → confirm 401 and the log line shows 401 with no secret.
5. Trigger a 500 (e.g. temporarily point `DATABASE_URL` at an unreachable host and hit a DB-backed route) → confirm the 500 response is `{"detail": "Internal Server Error"}` and the error log shows a scrubbed traceback with no frame locals.

## Performance Considerations

- The middleware adds one `time.perf_counter()` call and one `logger.info()` per request — negligible overhead (sub-microsecond timing + a formatted string write to the root logger's handler).
- `_scrub_traceback` runs only on the 500 path (exception), not per-request — its cost is irrelevant to the hot path.
- No request body or response body is read or buffered by the middleware — no memory or latency impact on large responses.
- Silencing uvicorn's access log (`--no-access-log`) *reduces* log volume by one line per request.

## Migration Notes

No database migration. No data model changes. The middleware is additive — it wraps the existing app without modifying any route handler or existing middleware. Rollback is removing the `app.add_middleware(RequestLoggingMiddleware)` line, the exception handler, and the `--no-access-log` flag.
